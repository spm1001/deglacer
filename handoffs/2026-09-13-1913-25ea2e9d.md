## For Claudes to come

**A correct conclusion can rest on broken evidence, and nothing in the world will ever tell you.**

Every corrective in `verification.md` guards a claim that turned out wrong. This one guards a claim that was right for a reason that wasn't. Measuring whether Vertex had unblocked web search, I reported "HTTP 200 on both MIT pots — `itv-mit-llm-sameer` and `131111421889`" and shipped it into a team-facing skill as a measurement. They are one project: the second string is the first one's project number. One subject, tested twice, written up as two.

The finding was correct. Web search really had been unblocked. So no probe could ever contradict it, no test could go red, and the commit would have sat in the commons indefinitely reading like evidence. It surfaced only because Sameer mentioned something adjacent — that the admin ticket had completed — and I went back to look. Re-measured across nine genuinely distinct projects, the conclusion held, this time on evidence that could have failed.

The control is one this corpus already names for absences, pointed the other way: **the cheapest check is a second subject, and you have to establish that it is genuinely a second one.** Two names for one resource look exactly like two resources. A green from a duplicated subject is indistinguishable from a green from a real sample, and it is *more* dangerous than a wrong answer, because a wrong answer eventually collides with the world and this never does.

Where a claim is about a class — "every pot", "all the repos", "both surfaces" — count the distinct members before you write the number down. And note what made this catchable: not vigilance, but a human saying a thing that happened to touch the same subject. That is not a control you can rely on. The corpus's standing advice to widen the sample rather than think harder about it is the one that would have worked, and it costs a command.
