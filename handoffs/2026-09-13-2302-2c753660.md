## For Claudes to come

**With parallel tool calls, one `requestId` spans a tool round-trip.** CC (2.1.27x measured, 11 requests in one 800 KB file — `~/.claude/projects/-home-modha/74dd45ae-a5c8-4688-9fbd-d9a6423e008c.jsonl`, the "newest" fixture the oracle test picked by rule on 2026-09-13) writes block 0's assistant entry, runs that tool, writes its `tool_result` (and a `bash_output_audience_note` attachment), and only then writes block 1's assistant entry — same `requestId`, identical final `usage` on every entry, `apiBlockIndex` 0, 1, 2 ordering them. So "a request is a contiguous run of assistant entries" is false, and anything that groups a request by contiguity — a streaming usage dedupe, a per-turn merge that flushes on the first non-assistant line — splits the request and double-counts. `dedupe_by_request` keys globally and is right; a streaming reader must close a request group only on a *different* request or a new human turn. The synthetic fixture cannot teach this; the file did, on the first replay of a real jq program.

**A designed divergence has to be stated, not hidden, in an equivalence test.** `extract_human_text` strips `<task-notification>` / `<system-reminder>` / `<command-*>` blocks (as `--summary` always has), so a term living only inside such a block is in the raw line and not in the human row. The right move was to encode the permitted residue — raw-only lines must be human rows carrying a stripped tag — rather than weaken the comparison to "roughly the same". The same file showed CC now stamping `origin.kind` (`human` vs `task-notification`) and `promptSource` (`typed` vs `system`) on string-content user entries: a discriminator `is_human_message` does not read yet, so an injected notification classifies as `human` with empty text.

**Measure an alternative across every case before shipping it, and record the losers where the winner lives.** Two aggregation rules and a stopword list were each tried across all 26 bench cases; one rule tied and one lost, the stopwords moved one rank and cut whole-sentence query time by 4×. All three results sit in `index.py`'s docstring beside the rule that shipped, so the next person tempted by sum-of-top-3 finds the number rather than the argument.
