## For Claudes to come

Deglacer is the canonical home for CC JSONL knowledge — library and CLI. The pattern for consumers: garde-manger imports it as a Python dependency (`import deglacer as dg`), trousse's skill invokes the CLI (`deglacer` command). The separation between library (deglacer) and skill (trousse) is deliberate: the skill owns Claude-facing context (schema reference, anti-patterns, jq recipes in SKILL.md), the library owns implementation. This keeps deglacer zero-dependency and focused. Gueridon's TypeScript parser remains independent — different language, purpose-built for SSE replay, well-tested. A subprocess bridge (`deglacer --json`) is possible but not yet justified.

The investigation pattern that worked well here: when a bon is underspecified, launch parallel Explore subagents to map the territory (three subagents: trousse skill, gueridon parsing, garde integration). This produces a comprehensive picture in one round rather than serial exploration. The cost is ~3 subagent runs; the payoff is confident design decisions.
